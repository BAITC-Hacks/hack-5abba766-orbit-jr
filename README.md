# Career Quest

Платформа развития сотрудников: профиль и карьерная цель, разрывы в навыках, обоснованные следующие шаги, короткие учебные модули с проверкой знаний, история и HR-аналитика. Данные, уроки и результаты тестов сохраняются в PostgreSQL; влияние завершений на навыки моделируется отдельно.

## Структура

```text
backend/       серверная логика, PostgreSQL, авторизация, импорт, AI и тесты
frontend/      Next.js / React; страницы и тонкий HTTP-адаптер /api
contracts/     общие TypeScript-типы команды
scripts/       запуск приложения и проверки
compose.yaml   приложение + PostgreSQL
```

[Как пользоваться и понимать цифры](docs/PRODUCT_GUIDE.md) · [Бэкенд и его модули](backend/README.md) · [Архитектура](docs/ARCHITECTURE.md) · [Правила и API](docs/BACKEND.md) · [AI и оценка качества](docs/AI.md) · [История и качество рекомендаций](docs/RECOMMENDATION-QUALITY.md)

## Запуск всего проекта через Docker

Нужен работающий Docker с Compose. Первой сборке необходим интернет для образов и npm-пакетов.

1. Клонируйте репозиторий и перейдите в его корень.
2. Создайте локальную конфигурацию: `cp .env.example .env` (PowerShell: `Copy-Item .env.example .env`).
3. Из предоставленного организаторами архива положите **четыре файла непосредственно в `data/source/`**:

   ```text
   employees.json
   skills.json
   events.json
   activity_history.csv
   ```

4. Запустите:

   ```sh
   docker compose up --build -d
   ```

5. Откройте [http://localhost:3000](http://localhost:3000). Готовность: `docker compose ps`; логи: `docker compose logs app`.

Официальный датасет, `.env` и содержимое БД не публикуются в Git. Если исходных файлов нет при первом старте, приложение завершится с ошибкой bootstrap; подставных данных вместо них не будет. Успешно инициализированная база сохраняется между запусками и больше не требует исходных файлов для обычного рестарта.

| Логин | Пароль по умолчанию | Доступ |
|---|---|---|
| `employee` | `employee-demo-2026` | Первый сотрудник исходного набора, только свой профиль |
| `hr` | `hr-demo-2026` | Каталог сотрудников, выбор профиля, аналитика и импорт |

Это **demo-аккаунты для синтетического набора**. HR может менять цель и моделировать выполнение за выбранного сотрудника. Автор операции записывается отдельно от сотрудника. Пароли можно задать переменными `DEMO_EMPLOYEE_PASSWORD` / `DEMO_HR_PASSWORD` до первого запуска; изменение переменных не меняет пароли уже созданных аккаунтов.

Остановка: `docker compose down`. Данные останутся в именованном volume. Команда `docker compose down --volumes` **удаляет сохранённый прогресс, учебные попытки, импорты и сессии**; после неё новый запуск заново загрузит исходный набор. При обновлении приложения миграция `002_learning` добавляет хранение обучения, сохраняя существующие профили и изменения.

## Разработка на компьютере

Нужны Node.js 24, npm и PostgreSQL (базу удобно запускать в Docker). Команды выполняются **из корня репозитория**, используется корневой `package-lock.json`:

```sh
npm ci
cp .env.example .env
# Положите четыре файла в data/source, как описано выше.
docker compose up -d db
npm run dev
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Запуск автоматически применяет закоммиченные миграции и проверяет инициализацию набора. `backend/` — отдельный workspace-пакет; API вызывает его через `frontend/src/app/api/[...path]/route.ts`. Второй HTTP-сервер не нужен.

PostgreSQL доступен только локально на порту `54329`. Для другой локальной базы задайте `DATABASE_URL`. Для запуска собранной версии: `npm run build`, затем `npm start`. Не запускайте dev и Docker app одновременно на порту 3000.

## AI

Ранжирование реализовано через OpenAI-совместимый Chat Completions API со Structured Outputs. В `.env` задайте `LLM_API_KEY`, `LLM_MODEL` и при необходимости `LLM_API_URL`, затем перезапустите приложение. В `.env.example` указан `gpt-6-sol` с low reasoning: команда проверила эту конфигурацию на авторских синтетических примерах; [сохранённые измерения и ограничения](docs/AI_VERIFICATION.md). Этот отчёт не означает, что AI настроен в вашем запуске. Поддержку схемы JSON другого провайдера нужно проверить отдельно.

Без ключа или модели приложение полностью выполняет расчёты и показывает `rules_fallback`. Таймаут или неверный ответ AI также приводит к явно отмеченному подбору по правилам. Фактический вызов внешнего провайдера без настроенного ключа не выполняется. Интеграция проверяется автоматическими тестами с имитацией ответов; успешное подключение конкретной модели нужно проверить с вашим ключом.

Модель получает роль, грейд, цель, навыки и допустимые кандидаты одного сотрудника. ФИО, руководитель, пароли и полная история компании ей не передаются. Модель выбирает существующие ID и факты; числовой эффект и текст из фактов формирует сервер. Перед использованием внешнего API соблюдайте правила организаторов по обработке набора. Документация формата: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Сценарий проверки

1. Войти как `employee`, открыть «Обзор»: текущие навыки, цель и карьерный путь. На свежем официальном наборе это профиль `E0001`.
2. Получить рекомендации, раскрыть причины выбора и ожидаемый эффект. Карточки — альтернативы одного следующего шага; их приросты не складываются в готовый план.
3. Открыть «Учебную мастерскую» → «Демо-модуль: запрос, данные и надёжный повтор» (`EV_005`, System Design Fundamentals). В свежем профиле `E0001` эта активность доступна. Другой доступный модуль можно открыть из карточки рекомендации или истории.
4. Изучить первый урок и отметить его завершение. Закрыть и снова открыть модуль: завершённый урок сохранён. Пройти оставшиеся два урока по порядку.
5. Ответить на все три вопроса, намеренно ошибившись хотя бы в одном. Нажать «Проверить ответы»: сервер вернёт результат и пояснения, навыки пока не изменятся.
6. Исправить ответы по материалу и пройти проверку на 100%. Увидеть подтверждение модуля, расчётный прирост навыков и изменение покрытия цели. Вернуться к профилю: история и рекомендации обновятся. Повтор успешного запроса не начисляет эффект снова.
7. Войти как `hr`, открыть общий срез и выбранного сотрудника. Сравнить исходное участие с состоянием после симуляций; посмотреть дефициты навыков и причины отсутствия следующего шага.
8. В импорте загрузить JSON сотрудников и/или CSV истории, выполнить предварительную проверку и подтвердить добавление. Новые ID добавляются, идентичные записи пропускаются, изменённые существующие ID отвергаются без частичной записи.
9. Перезапустить приложение: цель, учебная попытка, результаты проверки и сценарный прогресс останутся.

Если активность уже завершена в сохранённой базе, повторное начисление недоступно: откройте сохранённый результат или выберите через HR сотрудника, которому активность ещё доступна. Для другого исходного набора допуск определяется его данными, а не жёстко заданным ID.

Доступны **два авторских модуля по 7 минут**, в каждом три урока и три вопроса: надёжные функции Python (`EV_012`, фрагмент 24-часового курса) и надёжная обработка запросов (`EV_005`, фрагмент 16-часового курса). Чтение и тест проходят внутри приложения; AI и установленный Python для них не нужны. Сервер хранит попытку и проверяет ответы. После успешной проверки он **симулирует полный каталоговый эффект активности**, чтобы показать пересчёт траектории. Это не утверждение, что за 7 минут пройден весь исходный курс или подтверждён профессиональный уровень.

## Автоматические проверки

Результаты загрузки официального набора, проверки расчётов и текущие ограничения:
[проверка датасета](docs/DATASET_VERIFICATION.md).

```sh
npm test
# Изолированные временные PostgreSQL-схемы; live-демо не очищается:
TEST_DATABASE_URL=postgresql://career_quest:career_quest_local@127.0.0.1:54329/career_quest npm run test:integration
npm run build
npm run eval:ai
```

Для PowerShell сначала задайте `$env:TEST_DATABASE_URL="postgresql://career_quest:career_quest_local@127.0.0.1:54329/career_quest"`, затем `npm run test:integration`.

`npm run eval:ai -- --suite=all` проверяет ранжирование по правилам на 23 авторских синтетических случаях и два пустых результата без сети. `--suite=domain` отдельно запускает шесть случаев через доменный расчёт и оба пустых состояния; без выбора набора запускаются семь исходных случаев. `npm run smoke:ai` и `npm run eval:ai -- --live --suite=all --repeat=3` используют провайдера и требуют ключ и модель в корневом `.env`. `npm run verify:ai-flow -- --live` проверяет сквозной серверный сценарий на временной PostgreSQL-схеме и двух живых AI-запросах; требуется `TEST_DATABASE_URL`. Результат offline-проверки не доказывает качество живой модели; детали метрик — в [AI.md](docs/AI.md).

`npm test` запускает unit-тесты backend и клиентские тесты frontend. Они проверяют начисления, границы уровней, цели, prerequisites, повторы, проверку AI и взаимодействие интерфейса с API. Интеграционные тесты проверяют HTTP, сессии/права, конкурентные изменения, идемпотентность, атомарность импорта и сохранение при рестарте. Обучение проверяется отдельно: приватность ответов, порядок уроков, неуспешная проверка без начисления, успешная проверка с атомарным начислением, повторы и сохранение версии материала. Интеграционный запуск требует `TEST_DATABASE_URL`; без неё он явно завершается ошибкой. CI использует самостоятельно созданные fixtures. Дополнительный аудит официального набора запускается unit-тестами, если файлы есть локально.

## Допущения

- Дата расчётов берётся из `meta.as_of_date`, в исходном наборе это 2026-10-01. Время сессий и журнала действий — настоящее.
- Навыки профиля отражают последнюю аттестацию. До неё завершения повторно не начисляются. Для self-paced обучения отдельная дата завершения отсутствует; используется поле `date`.
- Пройденный короткий модуль и результат его теста сохраняются как учебная попытка. Новые выполнения каталоговых активностей и их прирост навыков — **симуляции**. 100% мини-теста, 100% модуля и 100% покрытия требований цели обозначают разные вещи; ни одно из них не означает автоматического повышения.
- Приложение работает с одной компанией; создание произвольных аккаунтов, кадровые интеграции, email, фоновые очереди и оценка под высокой нагрузкой не входят в текущую реализацию.
