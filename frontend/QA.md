# Проверка интерфейса — 23 сентября 2026

Проверена рабочая версия frontend на базе `0fc690a`, с синтетическими HTTP-ответами через отдельный локальный QA-сервер. Это проверка клиента; настоящий backend и его авторизация в этом checkout ещё не подключены.

## Исправления

- Длинные имена и карьерные цели переносились некорректно на телефоне. Исправлены переносы, сетки карточек, мобильная навигация и размеры элементов управления. Широкие HR-таблицы прокручиваются внутри своего контейнера.
- Начальный ответ session 401 больше не показывает ложное сообщение об истёкшей сессии. Неверный пароль получает отдельное сообщение. Заблокирован повторный submit формы входа.
- Повтор завершения или импорта после HTTP 408/429 сохраняет исходные тело запроса и Idempotency-Key: неоднозначный ответ не означает отмену операции сервером.
- Выбор цели открывается с текущим значением. Запланированная активность без даты подписана «Дата не указана», включая модальное окно.
- Исправлены возврат фокуса после ошибки входа, очистки поиска и закрытия модального окна; открытие HR-профиля переводит фокус к профилю, закрытие — обратно к сотруднику.
- HR-поиск отправляется с задержкой 300 мс, пустые параметры пропускаются. Пагинация блокируется при загрузке. Ошибки импорта показывают файл, строку и поле.

## Дополнения

- Фильтр истории по статусу и счётчик результатов.
- Переключатель «Только навыки с разрывом».
- Показ/скрытие пароля, сброс фильтров каталога, ссылка перехода к содержимому с клавиатуры.
- Читаемые названия навыков в HR-сводке и сравнение уровней в результате завершения.

## Повторить браузерную проверку

Из `frontend` в первом терминале:

```powershell
npm run build
npm run start -- --port 3200
```

Во втором терминале, также из `frontend`:

```powershell
node tests/preview-server.cjs
```

Открыть `http://localhost:3201/__qa` и выбрать сценарий. Для сценария login подходит любой логин и тестовый пароль `qa`. Для проверки импорта использовать `tests/fixtures/ui-import.json`.

QA-сервер слушает только 127.0.0.1 и не загружается приложением Next.js. Его сценарии используют общее состояние в памяти, поэтому предназначены для одного последовательного прогона. Переход к сценарию сбрасывает состояние.

Реальные cookie/права, атомарность импорта, серверное начисление и persistence, вызов LLM и развёртывание требуют отдельного интеграционного прогона после появления HTTP-обработчиков. Тестовые ответы этих гарантий не подтверждают.
