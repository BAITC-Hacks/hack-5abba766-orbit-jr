# Career Quest — UI prototype

Самостоятельный frontend на Next.js / React / TypeScript. Референс: композиция, типографика и кнопки apple.com; графика создана CSS, материалы Apple не скопированы.

## Запуск

Требуется Node.js 22 LTS. Все команды выполняются из папки `frontend`:

```powershell
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:3000. Страницы: `/employee`, `/hr`, корневая `/`.

```powershell
npm run typecheck
npm run build
npm start
```

## Что реализовано

- Адаптивный обзор сотрудника, траектория, шкалы навыков и приоритетов.
- Каталог с поиском и фильтрами, карточки с объяснениями и ожидаемым эффектом.
- Добавление в план, симуляция завершения без повторного прироста, история.
- Смена демонстрационной цели Senior/Lead и пересчёт прогресса.
- Сохранение действий в localStorage, сброс демо.
- HR-предпросмотр с фильтрацией отдела и отдельной маркированной выборкой.
- Локальная предварительная проверка JSON, ошибки файла. Не настоящий импорт.
- Доступные native dialog, Escape, фокус, мобильная версия, reduced motion.

## Интеграция

Это UI-демо: реального backend, авторизации и LLM нет. Все данные в `src/lib/demo.ts` созданы для интерфейса и не являются исходным датасетом. HR-показатели — отдельные фикстуры, не синхронизированы с действиями сотрудника. Цель Lead — демонстрационное увеличение требований, не реальные role_profiles.

`src/lib/api.ts` содержит асинхронный HTTP-транспорт и адреса из архитектурного документа. Он пока не вызывается UI: подключить согласованные Zod-контракты вместо локальных фикстур. Не включать тихую подмену реальных API-ошибок демо-данными.

Контракты теперь определены в [contracts/backend.ts](../contracts/backend.ts), правила сервера — в [docs/BACKEND.md](../docs/BACKEND.md). Перед подключением API: вынести состояние в hooks; распаковывать ApiResponse<EmployeeView>; независимо загружать RecommendationResult; сравнивать version с парой dataset_revision/employee_revision после завершения и импорта. PUT goal и POST recommendations/completions передают expected_version; POST completions также передаёт Idempotency-Key и simulation=true. В реальном режиме убрать переключение ролей без сессии и localStorage как источник бизнес-данных. Режимы ai, rules_fallback и no_candidates отображаются явно; coverage из API — доля 0–1, интерфейс умножает её на 100.

В HTTP-транспорте сохранять error.code/details, чтобы обрабатывать конфликты версий и импорта. Клиентский timeout рекомендаций должен быть больше серверного бюджета 10 секунд, например 12 секунд, чтобы получить fallback-ответ. Карточки рекомендаций — альтернативы следующего шага; их ожидаемые приросты не складываются. После выполнения состояние и рекомендации запрашиваются заново. Цель и требования берутся из role_profiles, не из демонстрационного увеличения всех требований Lead.

Приложение размещено в `frontend/`: исходники в `frontend/src`, зависимости и конфигурация рядом. Все относительные пути выше указаны от `frontend/`. Общая архитектура сохранена в `../docs/ARCHITECTURE.md`. Выбран backend внутри того же Next-проекта: модули в `src/server`, HTTP-обработчики в `src/app/api`. Запросы остаются same-origin; отдельный сервер, proxy и CORS не нужны. Tailwind не требуется этому UI: стили находятся в одном CSS.

Шрифт Manrope загружается из Google Fonts; при отсутствии сети используются системные sans-serif. Иконки lucide-react. Внешние изображения и ключи API не требуются.
