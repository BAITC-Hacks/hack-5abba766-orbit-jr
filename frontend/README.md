# Career Quest — frontend

Next.js App Router, React, TypeScript и обычный CSS. Исходный дизайн сохранён.

## Запуск

Node.js 22 LTS. Из корня репозитория:

```powershell
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:3000/employee или /hr. Рабочий режим проверяет серверную
сессию; без API показывает ошибку, а не фиктивный профиль. Подготовленный UI-прототип
доступен только при явном переходе на /demo. Его localStorage не используется рабочими страницами.

```powershell
npm test
npm run typecheck
npm run build
npm start
```

Если порт занят: `npm run dev -- --port 3100`.
Для будущего контейнера добавлен `npm run start:container` (0.0.0.0:3000).
Docker Compose, bootstrap, SQLite и серверные обработчики пока отсутствуют;
`docker compose up --build` ещё не является рабочей командой этого checkout.

## Контракты и HTTP

Используется общий [contracts/backend.ts](../contracts/backend.ts), полученный из
origin/main (fd6292d). Локальные серверные сущности не создавались. Типы пока
декларативные: общих runtime Zod-схем команда ещё не предоставила. Транспорт
проверяет envelope, сохраняет HTTP status, error.code/details и request_id;
полная runtime-валидация ответа остаётся задачей интеграции общих схем.

Клиент вызывает согласованные маршруты (реальные обработчики пока не реализованы):

| Метод | Путь | Использование |
|---|---|---|
| POST | /api/auth/login | Подготовленный аккаунт |
| GET | /api/auth/session | Сессия и роль |
| POST | /api/auth/logout | Выход |
| GET | /api/employees | Пагинация и фильтры разрешённого HR-списка |
| GET | /api/employees/:id | Профиль, цель, прогресс, история |
| PUT | /api/employees/:id/goal | Выбор роли/грейда из каталога |
| POST | /api/employees/:id/recommendations | Отдельная загрузка AI / rules_fallback / no_candidates |
| POST | /api/employees/:id/completions | Симуляция, ожидаемая версия и Idempotency-Key |
| GET | /api/catalog | Справочник навыков, целей и мероприятий |
| GET | /api/hr/overview | Общая разрешённая HR-выборка |
| POST | /api/import | multipart employees (JSON), history (CSV), expected_dataset_revision, dry_run=false |

Все адреса относительные, cookie same-origin, запросы без кэша. Клиентский таймаут
15 секунд сохраняется и при передаче AbortSignal. Никаких ключей LLM в клиенте нет.
API предполагается в frontend/src/app/api в том же процессе Next.js.

## Реализованное поведение клиента

- Навигация по серверной роли; 401 переводит к форме входа, 403 показывает отказ.
  Это не замена проверкам прав backend.
- Профиль не ждёт рекомендаций. Навыки, требования, разрывы, цель и coverage
  поступают с сервера; UI только переводит coverage из доли в проценты.
- Источники imported/selected/suggested/missing различаются. Lead без цели
  предлагает выбрать направление. Выбор другой профессии использует role_profiles.
- Версии сравниваются по обеим координатам dataset_revision/employee_revision.
  Ответы отменённых запросов и старых поколений игнорируются. После изменения
  цели, завершения или импорта профиль и рекомендации обновляются.
- Повтор завершения после неоднозначной сетевой ошибки сохраняет точные тело и
  Idempotency-Key. Двойное нажатие блокируется; optimistic начисления нет.
  Receipt replay показывает сохранённый результат, затем получает актуальный профиль.
- История показывает все шесть статусов, simulation и superseded attempts.
  EV_036 различается participation_id либо event_id + session_date.
- HR-импорт отправляет JSON/CSV, проверяет суммарный лимит 20 МиБ, показывает
  серверные ошибки/строки/поля, конфликт IDs, счётчики и предупреждения.
  После успеха обновляются HR, каталог, список и открытый профиль.
- HR-сводка отделяет исходные наблюдения от симуляций, источники целей и
  знаменатели разрывов. Фильтры относятся только к таблице сотрудников:
  контракт HrOverview не содержит параметров фильтрации сводки.
- Каталог сохраняет поиск и фильтр типа. Допуск и зачисление не выдумываются:
  CatalogView не содержит персональных причин блокировки, API зачисления нет.
- CSS, системные шрифты без внешнего запроса, focus-visible, native dialog,
  Escape/возврат фокуса, live regions, reduced motion и мобильные стили.

## Разделение файлов

- src/components/quest-app.tsx — сессия и композиция рабочего интерфейса.
- src/components/quest/ — login, navigation, employee, skills, history,
  recommendation-card, modal, hr, hr-overview, import-panel, feedback.
- src/hooks/use-employee.ts — независимые запросы, отмена, версии, мутации/повторы.
- src/hooks/use-resource.ts — загрузка справочников, списков и сводки.
- src/lib/api.ts — транспорт; src/lib/labels.ts — русские подписи enum.
- src/components/demo-quest-app.tsx и src/app/demo/page.tsx — изолированный старый прототип.
- tests/client.test.cjs — клиентские проверки на синтетических HTTP-ответах.

## Проверки и ограничения

Клиентская проверка: `npm run test:client` (12 тестов); `npm test` также запускает тесты AI/domain. Проверены клиентские тесты, `npm run typecheck`, `npm run build`.
Клиентские тесты покрывают отмену/устаревшие версии, независимый профиль,
идемпотентный повтор, блокировку двойного клика, replay/refetch, multipart,
конфликт атомарного импорта без ложного успеха, 401 и HR-ограничение интерфейса,
разные режимы рекомендаций и отсутствие цели. Тестовый React renderer выдаёт
предупреждение deprecation; тесты завершаются успешно.

В браузере проверены отсутствие API без тихого fallback, явный /demo,
мобильная ширина 390 px и модальное окно прототипа. Это не сквозная проверка
реального employee/HR-сценария. Backend, настоящая авторизация, AI, атомарность,
недопущение двойного начисления сервером, SQLite persistence и Docker не проверены.

До завершения интеграции нужны:

1. Route Handlers и серверная проверка прав по общему BackendApi.
2. Общие Zod-схемы и export runtime-валидаторов из contracts (без параллельной модели типов).
3. Локальные подготовленные аккаунты, cookie/Origin-политика и тестовый набор.
4. Реализация completion/import receipts, версии и SQLite volume.
5. Docker/миграции/bootstrap от интегратора; подключение уже добавленных командой AI-адаптера и baseline к HTTP API.
6. Если нужны дополнительные функции: контракт зачисления, персонального допуска,
   справочник доступных отделов и фильтрованная HR-сводка.

Ожидающий повтор хранится в памяти открытого экрана; после перезагрузки клиент
получает серверное состояние. Сервер обязан обеспечивать идемпотентность участия
независимо от жизни вкладки. Полная локализация не заявляется: названия/ID из
серверных справочников показываются как получены.
