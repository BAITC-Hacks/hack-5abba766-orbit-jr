# Проверка официального набора: 23 сентября 2026

Проверен локально предоставленный синтетический набор Career Quest на базе
коммита `aa68d74`. Исходные файлы и ключи API не включены в Git.

## Загрузка и расчёты

- Четыре исходных файла скопированы в `data/source/`; SHA-256 копий совпадает с источником.
- Штатный `loadDataset` успешно проверил схемы, уникальность ID и связи.
- Загружены 200 сотрудников, 60 навыков, 32 профиля требований, 40 активностей
  и 2 743 записи истории. Дата расчёта — `2026-10-01`.
- `npm run bootstrap` применил миграции и загрузил набор в локальный PostgreSQL.
  Проверка `source_fingerprint` подтвердила совпадение БД с исходными файлами.
- Из состояния БД построены профили всех сотрудников и HR-сводка на 200 человек.
  Для 161 сотрудника есть допустимый целевой шаг; всего 474 кандидата.
  У остальных: 10 без цели, 26 без подходящего к цели события, 3 без полезного прироста.
  Пустые результаты не подменяются выдуманными рекомендациями.

Аудит `backend/tests/domain.dataset.test.ts` теперь использует тот же загрузчик,
что приложение. Ранее он вручную собирал snapshot, обходя проверку входных данных.
Полностью отсутствующий локальный набор пропускается для CI; частично скопированный
набор завершает проверку ошибкой с именами недостающих файлов.

Тест проверяет каждый допустимый вариант независимо: смоделированное завершение
даёт ровно обещанный прирост навыков и покрытия цели. Также проверяются начатое
обучение предыдущего грейда, дублирующиеся попытки и разделение истории/симуляций в HR.

состояние демо. Единственный новый внешний AI-запрос использовал авторский
синтетический пример, а не официальный набор. Он подтверждает подключение,
валидность ответа и ожидаемый выбор в одном случае, но не преимущество AI над правилами.

## Границы проверки

При следующем углублённом аудите добавлен третий локальный тест: полная цепочка
baseline-шагов каждого из 200 профилей до объяснимой остановки. Он проверяет
отсутствие циклов и повторных эффектов, точность обещанного прироста, границы
уровней, монотонность покрытия и неизменность исходного набора. Все три теста
прошли. Это локальная симуляция правил; достижение цели для каждого сотрудника
и качество выбора LLM этим не утверждаются.

Проверены файлы, настоящий PostgreSQL, доменная логика, HTTP handlers и сборка.
Сквозная браузерная проверка актуального Next-сервера не выполнена: существующий
процесс на порту 3000 возвращал 404 для `/api/health`, а автоматическая проверка
окружения отклонила отдельный фоновый запуск на 3001 с `blocked by policy`.
Эти ограничения не обозначены как успешная проверка интерфейса.

Обычный повторный bootstrap сохраняет уже загруженную базу. Замена файлов
`data/source/` сама по себе не заменяет данные и прогресс в существующей БД.
Дополнительные профили и историю следует добавлять через предусмотренный импорт.
