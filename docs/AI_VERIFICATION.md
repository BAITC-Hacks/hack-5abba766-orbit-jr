## Сценарий с настоящими PostgreSQL и моделью

Команда `npm run verify:ai-flow -- --live` прошла 3/3 проверки. Она создаёт
изолированную случайную PostgreSQL-схему с синтетическим сотрудником и выполняет
авторизованные HTTP Request/Response handlers:

1. SQL = 1: AI рекомендует продолжить начатый базовый курс.
2. Completion начисляет SQL 1 → 2 ровно один раз; повтор с тем же ключом воспроизводит квитанцию.
3. С новым snapshot AI выбирает открывшийся продвинутый курс; старый snapshot даёт 409.
4. Второе completion меняет SQL 2 → 3; цель достигнута, рекомендации пусты с `GOAL_REACHED`.
5. HR отражает симуляции отдельно от исходной истории.
6. Импорт новых ID сотрудника и истории меняет рекомендации без правок кода; права employee соблюдаются.

Два настоящих запроса GPT-6 Sol заняли 5347 и 2566 мс на границе HTTP handler.
Управляемая гонка дополнительно проверена локальным HTTP mock провайдера: 429 для
одновременного подбора и 409 для изменившегося за время ответа snapshot.
[Полный отчёт](verification/2026-09-23-ai-flow.json) явно различает эти режимы.
Этот runner не измеряет браузер или TCP-сервер Next.

## Регрессии и автоматические проверки

- `npm test`: 270 backend-тестов прошли. После получения нового frontend
  `npm run test:client -w frontend`: 23/23 клиентских теста прошли.
- `npm run test:integration`: 13 прошли, один opt-in live тест пропущен;
  он отдельно пройден в указанном выше живом сценарии.
- Offline evaluation: все 17 авторских случаев, AI-метрики `null`, сетевых вызовов нет.
- `npm run typecheck` и `npm run build`: оба workspace прошли, production build успешен.

Дополнительный TCP/browser smoke не выполнен. Автоматическая проверка окружения
отклонила как фоновый, так и управляемый терминальный запуск Next на локальном
порту 3137 с причиной `blocked by policy`, без подробного объяснения. Поэтому
сборка и handler-интеграция не обозначены как пройденная браузерная проверка.

Первый холодный integration-запуск завершился `Hook timed out in 10000ms` при
подготовке fixtures/импорте модулей. Таймаут setup поднят до 30 секунд, рабочий
дедлайн AI не менялся. Итоговый общий integration-прогон прошёл за 5,34 секунды.

Воспроизведено и исправлено истощение пула: десять ожидающих AI-запросов блокировали
GET профиля. Теперь advisory locks используют отдельный пул, а HTTP cancellation
доходит до адаптера и освобождает реальную блокировку. Новый PostgreSQL-тест
проверяет обе ситуации. Предел на процесс: 10 обычных + 10 AI-соединений;
переполнение AI-пула ограничено секундой ожидания и возвращает 503.

Независимая проверка нашла незакрытый поток тела HTTP 503 провайдера. Адаптер теперь
прерывает такой транспорт сразу; регрессия использует настоящий локальный HTTP
сервер с незавершённым телом ответа.

## Что эти результаты не доказывают

- Превосходство LLM над baseline. Prompt задаёт те же правила, числовые факторы
  рассчитываются общим кодом, реальные кандидаты уже сортируются baseline.
- Обобщение на скрытые профили жюри: случаи авторские, часть добавлена после review.
- Полезность кадрового решения в эксплуатации: независимой экспертной разметки нет.
- Работу на полном официальном наборе и запуск поставки на машине жюри.

Для воспроизведения нужен Node 24, `npm ci`, ключ и модель в корневом `.env`.
Для PostgreSQL-проверок дополнительно нужен `TEST_DATABASE_URL` к тестовой БД;
таблицы live-демо не используются. Не публиковать `.env` и официальные данные.
