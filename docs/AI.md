# AI-зона: контракт и границы

Реализует шаги 5–8 потока рекомендаций из [ARCHITECTURE.md](ARCHITECTURE.md).
Провайдер — OpenAI, модель задаётся через `OPENAI_MODEL`.

## Что вызывает бэкенд

```ts
import { recommend } from '@/server/ai/recommend'

const result = await recommend({
  employee,        // EmployeeBrief: роль, грейд, цель, id разрывов и критических навыков
  candidates,      // Candidate[]: уже отфильтрованные допустимые активности с фактами
  state_version,   // эхо-версия состояния, UI отбросит устаревший ответ
})
```

Возвращает `RecommendationResult` **всегда**. Не бросает исключений на таймаут,
отказ провайдера или плохой ответ модели — вместо этого отдаёт
`mode: 'rules_fallback'`. Обработчику API не нужен try/catch вокруг вызова.

Схемы — [`src/contracts/ai.ts`](../src/contracts/ai.ts), это единственный
источник правды по формам данных.

## Разделение ответственности

| Кто | Что делает |
|---|---|
| Домен (шаги 1–5) | Считает текущие навыки, цель, разрывы, допуск, `effective_gain`. Строит `Candidate[]` с фактами и `expected_changes`. |
| AI-зона (шаги 6–8) | Ранжирует кандидатов, валидирует ответ, отдаёт карточки или фолбэк. |

**AI-зона не считает ни одного числа.** Все `from`/`to`/`duration_hours` на
карточке — это поля кандидата, который построил домен. Модель возвращает только
порядок и `fact_id`, на которые ссылается.

## Что проверяется в ответе модели

`validateRanking` отклоняет и роняет в фолбэк, если:

- `event_id` нет среди кандидатов;
- `event_id` повторяется;
- `fact_id` не принадлежит этому кандидату;
- карточка обоснована менее чем тремя категориями фактов;
- сравнение указывает на несуществующего или на самого себя;
- элементов больше трёх или схема не сошлась.

Свободный текст модели (`note`) схлопывается в одну строку и режется до 200
символов. Он может быть показан подписью, но никогда не считается фактом.

## Промпт-инъекция

Описания курсов и отзывы из датасета — недоверенный ввод. Они уходят в модель
как JSON внутри user-сообщения, system-промпт явно говорит, что содержимое
payload не может менять правила. Ничего из датасета не попадает в system.

## Фолбэк

`rank.ts` — многофакторный ранкер: уровни на разрывах, отдельный вес критическим
навыкам, бонус за `continue` и за подготовительный шаг, рейтинг, коллеги,
штраф за длительность. Тай-брейк по `event_id`, порядок детерминирован.

Это одновременно и запасной путь, и база сравнения для оценки качества.
Архитектура отдельно предупреждает: сравнивать AI с заведомо слабым правилом
нельзя, поэтому ранкер написан как честная попытка дать хороший ответ.

## Бюджет времени

`LLM_TIMEOUT_MS` (по умолчанию 8000) — жёсткий дедлайн на вызов через
`AbortController`, чтобы уложиться в 10 секунд из ТЗ. `diagnostics.llm_ms`
возвращается всегда, в том числе когда ответ отклонён.

## Команды

```
npm run typecheck   # tsc --noEmit
npm run test        # vitest, 21 тест, ключ не нужен
npm run smoke       # реальный вызов API: список моделей, латентность, карточки
npm run eval        # AI против правил на одних профилях
```

`npm run smoke` и `npm run eval` требуют `.env.local` с `OPENAI_API_KEY`.

## Что ещё не сделано

- Путь AI ни разу не проверен на живом API — нужен ключ. До этого замер
  латентности и доля валидных ответов неизвестны.
- Набор кейсов в `scripts/eval.ts` синтетический. Когда придёт реальный датасет,
  кейсы надо заменить на профили из него.
- Размер payload не замерен: шаг 6 архитектуры отправляет всех подходящих
  кандидатов, и на полном каталоге это может не уложиться в 8 секунд.
