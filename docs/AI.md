# AI-зона Career Quest

AI-реализация команды, включая проверки фактов и evaluation из `9b577ec`, перенесена в серверный workspace и интегрирована с доменным ядром. **В приложении один адаптер провайдера и одна реализация baseline.** Прежние исполняемые модули и AI-тесты из `frontend/src/server` и `frontend/tests` перенесены в `backend/`.

| Файл | Ответственность |
|---|---|
| `backend/src/ai/prompt.ts` | Промпт команды, компактный snapshot и JSON Schema |
| `backend/src/ai/adapter.ts` | Единственный HTTP-вызов провайдера, timeout, типизированные причины отказа |
| `backend/src/ai/response-validator.ts` | Строгая Zod-схема, проверка ID/фактов и сборка карточек |
| `backend/src/ai/recommend.ts` | Общий подбор AI/fallback для сервиса и evaluation |
| `backend/src/ai/index.ts` | Совместимые функции ранжирования и проверки |
| `backend/src/domain/baseline.ts` | Единый детерминированный comparator и выбор фактов fallback |
| `backend/src/domain/baseline-signals.ts` | Негативные исходы последних терминальных попыток |
| `backend/src/domain/recommendation-evidence.ts` | Проверка полноты фактов перед AI и fallback |
| `backend/src/domain/index.ts` | Допуск, эффекты, подготовительные шаги, сигналы истории и вызов baseline |
| `backend/src/services/recommendations.ts` | Версии снимка, блокировка параллельного подбора, режимы ai/fallback/empty |

Общие формы данных — [contracts/backend.ts](../contracts/backend.ts). Модель не получает доступа к записи в БД и не определяет величину прироста навыков.

## Вызов

Recommendation service получает допустимых кандидатов и обе карты сигналов из доменного ядра, затем вызывает:

```ts
const result = await recommend(input, { signals })
```

`recommend` готовит проверенный baseline, вызывает `rankWithModel(input, signal?)` и проверяет ответ. Транспорт возвращает `AdapterResult`, не бросая сетевые ошибки. Ошибки провайдера возвращают `rules_fallback` с причиной `missing_api_key`, `provider_timeout`, `provider_error` или `invalid_response`. Неполные или противоречивые серверные факты считаются ошибкой построения snapshot; они не превращаются в правдоподобное объяснение.

Пустой набор обрабатывается до адаптера как `no_candidates`; причину определяет домен. Fallback использует тот же comparator и полные сигналы истории и будущей пользы, что и доменное ядро.

Сервис проверяет версию до вызова и после ответа. PostgreSQL advisory lock ограничивает параллельный подбор одной employee/version; во время HTTP-вызова транзакция БД не удерживается. Изменившийся снимок отклоняется как `STALE_RECOMMENDATION`.

## Ground truth и проверки ответа

Промпт сохраняет подход команды: модель выбирает существующие candidate ID и факты, предпочитает закрытие критических разрывов, учитывает начатые активности и подготовительные шаги. Добавлено явное правило: карточки — альтернативы из одного состояния; будущие эффекты открываемого события ещё не получены.

В prompt попадают роль/грейд, цель, навыки и компактные кандидаты с проверенными фактами. ФИО, руководитель, свободные исходные описания и чужие профили не передаются. Текст payload обозначен как данные, а не инструкции.

Валидатор отклоняет:

- Неизвестные/повторные кандидаты, пустой список и больше `min(limit, количество кандидатов)` выборов.
- Факты другого кандидата, неизвестные и повторные ID фактов.
- Меньше трёх категорий из `grade`, `skill_gap`, `history`, `target_requirement`.
- Неизвестную альтернативу или альтернативу, уже входящую в выбранные рекомендации.
- Лишние поля, включая свободные объяснения и числовые обещания модели.

Карточки собираются исключительно из исходных серверных Candidate. Provider null в поле альтернативы нормализуется в соответствие с общими TypeScript-типами.

## Полный baseline

Comparator из командного `baseline.ts` встроен в `getCandidates` вместо прежней локальной сортировки. В нём исправлен расчёт прямой пользы:

```text
closed_gap = max(0, min(after, required) - min(before, required))
weighted_direct_gain = sum(closed_gap × (critical ? 2 : 1))
```

Навык вне целевых требований и рост сверх нужного уровня не увеличивают карьерную полезность.

Доменный код обязательно передаёт для **каждого** кандидата:

- `unlockedWeightedGain`: максимальную взвешенную пользу одного следующего открываемого события, рассчитанную после эффекта текущего шага;
- `negativeOutcomes`: число негативных исходов среди последних трёх терминальных попыток того же события.

Отсутствие сигнала считается ошибкой программирования. В production нет опционального default, который незаметно превращает полное ранжирование в упрощённое.

Порядок: закрытые критические разрывы → прямая польза + 0,5 × открываемая польза → меньше негативных исходов → меньшая длительность → предпочтение продолжения при равенстве → event ID → candidate ID. Карточки fallback используют проверенные факты и не выдумывают альтернатив.

## Конфигурация

- `LLM_API_KEY` и `LLM_MODEL` — оба обязательны для AI-режима. Непроверенного дефолта модели больше нет.
- `LLM_API_URL` — полный серверный URL Chat Completions; по умолчанию `https://api.openai.com/v1/chat/completions`.
- `LLM_TIMEOUT_MS` — по умолчанию 8000; фактический диапазон 100–8000 мс.

Используется один fetch-запрос без автоматических retries, с `store:false`, ограничением `max_completion_tokens=1400` и JSON Schema. Endpoint задаётся только серверным окружением; HTTP-пользователь изменить его не может. Внешний AbortSignal также поддерживается. Ключ не является `NEXT_PUBLIC_*`.

`isAiConfigured()` проверяет наличие непустых key/model и не обращается к провайдеру. Транспорт не возвращает наружу содержимое ошибки провайдера или секреты.

## Проверки

```sh
npm run typecheck -w backend
npm run test -w backend
npm run eval:ai
```

Командные тесты перенесены в `backend/tests/team-ai/` и `backend/tests/team-baseline.test.ts`. SDK-моки заменены контролируемым fetch; сохранены проверки структуры, фактов, альтернатив и comparator. Добавлены регрессии на прирост вне цели/сверх требования, обязательные сигналы, таймаут, явную модель, лишний model prose и повторные факты. Существующие проверки recommendation service на revisions и освобождение DB-соединения также сохраняются.

`npm run eval:ai` запускает авторские синтетические сценарии из `backend/evaluation/` без вызовов провайдера, даже если ключ настроен. Проверяются конкуренция критического и самого слабого навыка, история отказов, прирост вне цели и сверх требования, подготовительный шаг, продолжение и новые непривычные ID.

Для живой проверки задайте `LLM_API_KEY` и `LLM_MODEL` в корневом `.env`:

```sh
npm run smoke:ai
npm run eval:ai -- --live
```

Эти команды отправляют только авторские синтетические примеры. Отчёт разделяет baseline, принятые AI-ответы и fallback: fallback не засчитывается как совпадение AI с baseline. Измеряются ожидаемый первый выбор, корректность ссылок на факты, размер payload, задержка и режим ответа. Отсутствующие измерения AI в offline-режиме обозначены `null`. Совпадение с авторским ожидаемым ответом не является доказательством пользы продукта или качества на скрытых профилях жюри.

PostgreSQL/HTTP integration запускается отдельно; актуальные результаты общего набора фиксируются командами проверки проекта.

Живой провайдер в рамках интеграции не вызывался. Реальная задержка, доля валидных ответов и улучшение качества относительно baseline не подтверждены mock-тестами; для этих выводов нужен настроенный ключ и отдельная оценка.
