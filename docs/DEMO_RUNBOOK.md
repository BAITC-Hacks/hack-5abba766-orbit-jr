# Повторяемая демонстрация Career Quest за 180 секунд

Цель показа — доказать сохраняемый цикл «навык → допустимый шаг → модельный эффект
→ пересчёт». **Авторский синтетический набор**, один профиль, два курса и один
навык SQL. Он демонстрирует механику, а не качество на официальном наборе и не
результат реального обучения. Здесь подбор по правилам; live AI проверяется отдельно.

## Подготовить до выступления

Нужны Node.js 24, PostgreSQL и доступ к созданию схем в вашей локальной БД.
Исходные файлы организаторов для этой репетиции не требуются.

```sh
npm ci
docker compose up -d db
npm run build
npm run demo:prepare
npm run demo:start
```

`demo:prepare` создаёт уникальную схему `cq_demo_*`, проверяет и загружает авторский
набор, записывает только параметры репетиции в игнорируемый `.env.demo`.
Предыдущие схемы и общая БД не сбрасываются. Пароли именно новых аккаунтов этой
схемы: `employee / employee-demo-2026`, `hr / hr-demo-2026`.

`demo:start` проверяет конфигурацию и переопределяет даже унаследованный
`DATABASE_SCHEMA`, слушает только localhost на **3210**, отключает внешний AI для
повторяемости. Открыть [приложение](http://localhost:3210) и
[health](http://localhost:3210/api/health). Ожидание: `status=ok`,
`dataset_initialized=true`, `ai_configured=false`.

Проверить путь заранее; наличие успешной сборки само по себе не подтверждает
работу браузера. Если 3210 занят, сначала остановить именно предыдущий процесс
этой репетиции; не завершать посторонние приложения.

## Показ

| Время | Действие | Что доказываем |
|---|---|---|
| 0–25 с | Вход сотрудником. Показать Data Engineer Junior → Middle, SQL 1/3, покрытие 33%. Сказать: «Это авторская репетиция с модельными эффектами». | Цель и исходное состояние понятны. |
| 25–70 с | Открыть основания SQL foundations. Продолжить существующее участие через «Смоделировать выполнение». | Доступный шаг соответствует цели; симуляция явно названа. |
| 70–110 с | SQL стал 2, покрытие ≈67%. Появился Advanced SQL practice. Смоделировать его. | Предварительное требование открыло следующий шаг; эффект сохранён. |
| 110–135 с | SQL 3, покрытие 100%, причина «Навыки соответствуют выбранной цели». Обновить страницу. | Завершение цепочки и сохранение, без повторного начисления. 100% не означает повышение. |
| 135–160 с | Выйти, войти HR. Показать одного сотрудника и два симулированных завершения. | HR и сотрудник используют общие данные; исходная история отделена от симуляций. |
| 160–180 с | Открыть результаты [аудита](JURY_REVIEW.md). На официальных данных есть рост покрытия, но ноль полных целей в проверенном проходе. | Границы каталога и результата раскрыты честно. |

Для повторного показа остановить свой сервер (`Ctrl+C`), снова выполнить
`npm run demo:prepare`, затем `npm run demo:start`. Для проверки сохранности
перезапустить **только** `demo:start`, без новой подготовки: SQL останется 3.
Не запускать `docker compose down -v` и не очищать общую схему.

Учебный плеер — отдельный сценарий на официальном каталоге, он не входит в этот
трёхминутный показ. `/demo` — визуальная витрина на fixtures, не замена этому
сценарию с PostgreSQL.

## Короткие ответы жюри

- **Зачем LLM?** Она выбирает существующие кандидаты и акценты проверенных объяснений. На текущих авторских кейсах её первый выбор полностью совпал с правилами; преимущество для человека ещё проверяем. Надёжность механики не зависит от доступности модели.
- **Что означают проценты?** Доля выполненных требований модели навыков; избыточный навык не закрывает другой дефицит. Это не вероятность повышения.
- **Почему курс не предложен?** Проверяются аудитория, предварительные навыки, дата, уже учтённое выполнение и польза цели. Иногда правильный ответ — отсутствие шага и потребность расширить каталог.
- **Что реально сохраняется?** Цели, учебные попытки и моделируемые выполнения в PostgreSQL. Реальное профессиональное обучение и кадровые решения прототип не подтверждает.
- **Что дальше?** Подтверждение компетенций, завершения из LMS, управление аккаунтами и слепое сравнение полезности с HR. Доступы пока не получены.

Если приложение недоступно, прямо назвать показ резервным: использовать сохранённые
отчёты проверок, объяснить их границы. Не выдавать `/demo` или запись за живой API.
