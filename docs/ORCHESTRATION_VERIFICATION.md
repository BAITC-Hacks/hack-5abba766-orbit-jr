# Backend и AI: итог оркестрации 23 сентября 2026

Десять задач выполнены агентами `gpt-6-astra` с reasoning `ultra`, волнами
в пределах трёх одновременно работающих субагентов. Модель приложения по выбору
владельца — `gpt-6-luna`, `reasoning_effort=low`. Это готовая модель через API;
обучения весов и отдельного ML-сервера нет.

Backend-исправления объединены с командными изменениями обучения и интерфейса
в `7d65e7f`. Настоящий отчёт и финальная правка промпта добавлены следующим
коммитом. Чужая история Git сохранена; автор и коммиттер наших коммитов —
`ka1nyy <252775473+ka1nyy@users.noreply.github.com>`.

## Что сделали агенты

| № | Область | Подтверждённое изменение или результат проверки |
|---|---|---|
| 1 | Домен и навыки | Повторное обязательное участие больше не скрывается старым выполнением; допустимые ID вроде `toString` не дают значения из прототипа объекта. |
| 2 | Транзакции и импорт | Запрещена коллизия импортированного participation ID с ID симуляции. Проверены receipts, конкурирующие записи, revisions и полный rollback при поздней ошибке. |
| 3 | AI transport | Ответ ограничен 64 КиБ декодированных байт, проверяются UTF-8, envelope и завершённость ответа. Зависший reader и ошибка освобождают транспорт. |
| 4 | Входные данные | Проверяются NUL, одиночные суррогаты, коллизии ключей после trim, собственные critical skill IDs, даты найма и формат повторяемого события. Корректный Unicode остаётся допустимым. |
| 5 | HTTP и авторизация | Вход не создаёт сессию до проверки готовности данных. Logout отзывает сессию даже при последующем сбое метаданных; повтор без сессии допустим. Метаданные читаются без полной загрузки датасета. |
| 6 | Производительность | История индексируется внутри запроса. HR использует общие правила с ранним завершением поиска. Проверка актуальности после LLM читает две ревизии одним SQL-запросом. |
| 7 | Evaluation | Проверяется вся карточка, версия, принадлежность фактов и решающее evidence. Добавлены перестановки кандидатов, чужая история, граница окна и prompt-injection проверки. Повторы не выдаются за независимый holdout. |
| 8 | Поставка | Docker исключает вложенные env-файлы и тестовые артефакты. Integration runner переносим между ОС; отчёт относится к текущему запуску и не сохраняет прежний успех после сбоя. Проверены конкурентный bootstrap, rollback и рестарт. |
| 9 | Сохраняемое обучение | Начатый модуль можно корректно завершить после импорта соответствующего `in_progress`: цель попытки согласуется с участием под общей блокировкой, эффект начисляется один раз. |
| 10 | Независимый критический обзор | Повторно проверены транспортные границы, revisions, блокировки, обучение, HR parity и нормализация альтернатив. Воспроизведён оставшийся сбой Luna и проверена точечная правка промпта. |

## Живая оценка Luna

Все внешние запросы содержали только самостоятельно созданные синтетические
примеры. Исходные файлы организаторов и ключи не публикуются. Официальный набор
проверяется локально штатным загрузчиком; подробности —
[DATASET_VERIFICATION.md](DATASET_VERIFICATION.md).

Один набор содержит 23 авторских сценария ранжирования и две отдельные проверки
пустого результата. Три повтора дают 69 вызовов, а не 69 независимых профилей.
Оценка проверяет правильность первого выбора, весь контракт каждой карточки,
решающие ссылки и размеченный префикс порядка. Fallback не считается успехом AI.

| Состояние | Принятые AI-ответы | Все проверки | Отчёт |
|---|---:|---:|---|
| До нормализации необязательных сравнений | 66/69 | 66/69 | [Первый прогон](verification/2026-09-23-luna-before-normalizer.json) |
| После нормализации, до уточнения категорий и истории | 68/69 | 67/69 | [Второй прогон](verification/2026-09-23-luna-before-category-fix.json) |
| Финальный промпт | 69/69 | 69/69 | [Итоговый прогон](verification/2026-09-23-luna-final.json) |

В финальном прогоне нет fallback, неверных первых выборов или пропущенных
размеченных решающих фактов. Обе проверки пустого результата прошли. Задержка
границы рекомендации: p50 **2,487 с**, p95 **3,986 с**, максимум **6,783 с**.
В этот замер не входят исходная загрузка/расчёт домена, HTTP, БД и браузер.
JSON фиксирует SHA-256 промпта, схемы и случаев для воспроизводимости.
Результат подтверждает эти 69 вызовов, не гарантию будущих ответов.

Нормализация удаляет только необязательную ссылку сравнения на уже выбранную
карточку. Она не меняет ranking или evidence; неизвестные ID, чужие факты,
дубли choices и лишние поля остаются ошибкой. В последующей диагностике Luna
выбрала правильный шаг, но сослалась на `grade`, `target` и `unlock`: последние
два принадлежат одной категории `target_requirement`, поэтому валидатор
правильно отклонил ответ. Другой правильный выбор не сослался на решающую
историю сравнения форматов.

Промпт теперь явно различает число ссылок и число категорий; объясняет, когда
нужна ссылка на историю, даже если у выбранного формата недостаточно собственных
наблюдений; требует перед возвратом проверить категории, историю и unlock.
Валидатор и JSON Schema не ослаблены, факты за модель не подставляются.
Диагностика: исходный промпт 7/8 принятых ответов с воспроизведением ошибки,
уточнённый 6/6 с правильными выборами и всеми решающими ссылками.
[Целевые прогоны](verification/2026-09-23-luna-targeted-diagnostics.json).

## Производительность и пределы

Старый (`5543101`) и новый (`87499cd`) код сравнивались в одном процессе.
Полные результаты кандидатов, факты, сигналы и HR совпали во всех трёх наборах.
Масштабные синтетические fixtures прошли настоящий загрузчик схем и связей.

| Набор | Все кандидаты: было → стало | HR: было → стало |
|---|---:|---:|
| 200 сотрудников / 2 743 участия | 316 → 101 мс | 89 → 33 мс |
| 1 000 сотрудников / 50 000 участий | 55 929 → 1 637 мс | 1 121 → 69 мс |
| 1 сотрудник / 50 000 участий | 25 230 → 3 175 мс | 61 644 → 121 мс |

Это локальные наблюдения, не SLA; задержки растут при конкурирующей нагрузке.
Плотная история одного сотрудника всё ещё просматривается при подготовке
описательных фактов каждого кандидата. При росте таких историй следующий
шаг — переиспользовать агрегаты evidence внутри запроса, сохранив точный отбор
окон и фактов. [Агрегированные замеры](verification/2026-09-23-domain-performance.json).

Два пула PostgreSQL допускают суммарно до 20 соединений на процесс. Это нужно
учитывать при масштабировании числа экземпляров. Кэш гарантирует согласованность
на момент чтения снимка, а не последнюю версию на момент отправки ответа.

## Что остаётся непроверенным

- Полный браузерный путь и двухсекундный UI-отклик. Автоматическая проверка
  отклонила запуск отдельного Next-процесса: `blocked by policy`. Обходы этого
  ограничения не выполнялись. Production build не заменяет browser smoke.
- GitHub Actions не начал job из-за billing-блокировки аккаунта:
  `The job was not started because your account is locked due to a billing issue.`
  [Проверенный запуск](https://github.com/BAITC-Hacks/hack-5abba766-orbit-jr/actions/runs/35855319418).
  Это внешний блокер CI, локальные результаты приведены отдельно.
- Качество на скрытых профилях жюри, независимая экспертная полезность и рост
  фактической завершаемости обучения. Часть случаев создана после найденных
  ошибок, поэтому успешная регрессия не доказывает обобщение.

Сильнейший контраргумент к текущему AI-подходу: модель получает факторы той же
эвристики, что baseline; согласие с ней не доказывает дополнительную пользу LLM.
Решение стоит пересмотреть по слепой экспертной оценке на новых профилях с
конфликтующими факторами. Пока система обеспечивает проверяемое объяснение
и безопасный fallback, но не обещает безошибочность или превосходство модели.

## Воспроизведение

Из корня репозитория после настройки окружения по [README](../README.md):

```sh
npm test
npm run build
npm run test:integration
npm run eval:ai -- --suite=all
npm run eval:ai -- --live --suite=all --repeat=3
npm run verify:ai-flow -- --live
```

Integration требует отдельный `TEST_DATABASE_URL`. Live-команды расходуют API;
для них нужны серверные `LLM_API_KEY` и `LLM_MODEL=gpt-6-luna`. Старые результаты
Sol сохранены отдельно в [AI_VERIFICATION.md](AI_VERIFICATION.md).
