# Browser usability review

Дата: 2026-09-23. Второй специализированный проход существующего Astra high reviewer, а не пятый независимый агент: среда отказала в создании ещё одного agent thread. Первый проход этого reviewer — adversarial audit. Это ограничение независимости нельзя скрывать.

## Метод и границы

Все действия с UI — через mcp__cua_repl, собственная Chrome вкладка 36744700, сессия `🧪 AI usability`, приложение http://127.0.0.1:3105/. Использован skill ui-ux-pro-max: читаемый loading feedback, progressive disclosure, ясность действия, error recovery. Поиск skill database не выполнен: отсутствуют команды python и py; рекомендации опираются на прочитанные базовые правила, не на выдуманные search matches.

Открыты три профиля без изменения целей, конфигурации или прогресса: один no_candidates, два успешных AI (автоматическая загрузка при входе). Ручное обновление рекомендаций не нажималось; максимум два возможных live вызова, наличие cache из UI не определялось. Проверены раскрытые причины, conditional future benefit, демо-уроки, модальное окно активности и закрытие Escape. Имена/ID сотрудников, полные screenshots и сырые UI snapshots не сохранены в этот отчёт.

**Важная граница версии:** первая проверка выполнена до rebuild. Root и reliability reviewer установили, что запущенный app bundle старее актуального source prompt/adapter. Поэтому этот раздел — наблюдение старой работающей сборки, не доказательство UI результата нового prompt. Smoke после перезапуска должен быть добавлен отдельно.

## Вердикт до rebuild

Следующий шаг понятен, данные не маскируются под фактически заработанный рост. Критического UX-блокера в просмотренных happy/empty flows нет. Основной резерв — сделать решающую причину выбора заметной без чтения длинных технических фактов. Это полезный продуктовый интерфейс, но надпись AI сама по себе не показывает преимущества над правилами.

### Проверенные сильные стороны

- Есть отдельное состояние «Подбираем рекомендации. Профиль и история уже доступны», кнопка обновления отключена во время загрузки; страница профиля остаётся доступной. Точное cold latency не замерялось: overhead браузерного инструмента нельзя считать временем приложения.
- Успешный результат помечен «AI-подборка · проверенные сервером факты»; рядом явно сказано, что это варианты следующего шага и ожидаемые приросты не складываются. Три карточки не представлены трёхшаговым обязательным планом.
- Карточки показывают время, формат, дату и прирост к цели. В раскрытых объяснениях — конкретные навыки, текущий/будущий уровень, целевое требование и критичность. Это существенно полезнее общих фраз про мотивацию или потенциал сотрудника.
- Для direct activity с будущим unlock интерфейс объясняет отдельную последующую активность, условность пользы, необходимость повторной проверки расписания/допуска и то, что будущая польза не начисляется за подготовку. Это удалось проверить в настоящем AI-ответе.
- Карьерная цель прямо названа ориентиром; решение о повышении принимается отдельно. Существующие симуляции отмечены в прогрессе.
- «Открыть уроки» ведёт к учебному демомодулю с явным предупреждением, что короткий фрагмент не заменяет полный курс на 16 часов. Само открытие не отмечает завершение.
- «Подробнее о шаге» открывает модальное окно. Перед кнопкой завершения явно сказано, что отметка показывает расчётный деморезультат и не подтверждает посещение внешнего мероприятия. Ничего не завершалось. Escape закрыл модал и вернул фокус кнопке открытия.
- Empty state различает существующие разрывы и отсутствие подходящего каталожного шага; предлагает посмотреть навыки и обсудить подходящее обучение с HR. AI не изобретает доступный курс.

### P3: решающее объяснение скрыто за технической подробностью

Repro: открыть профиль с тремя AI карточками → раскрыть «Что даст обучение» у первой. До раскрытия видны порядковый номер, длительность, дата и coverage delta, но нет короткой решающей причины приоритета. После раскрытия появляются повторяющиеся уровни навыков и длинный абзац, включая вес критического навыка 2 и невзвешенных 1. Для HR чтение требует самостоятельно сопоставлять выгоды трёх карточек.

Предложение: показывать одну короткую server-grounded решающую причину рядом с карточкой, оставляя полный audit trail под details. Например, подтверждённое закрытие критического разрыва или условное открытие полезной следующей активности. Не создавать свободную причинную прозу и не обещать вероятность успеха по истории.

Сильнейший контраргумент: progressive disclosure снижает визуальную нагрузку, а подробные факты проверяемы и уже позволяют осмысленное решение. В данном демо цена ещё одного клика небольшая. Поэтому это улучшение понятности, **не blocker** и не доказательство плохого ранжирования. Консервативный guard с дополнительными history/effort citations увеличит длину, но сохранение истинных обязательных оснований важнее компактности; проблему длины лучше решать презентацией.

### P3: сообщение карьерного пути не совпадает с текущей загрузкой

Во время автоматической загрузки область «Следующий шаг» показывала «Подборка появится после обновления рекомендаций», одновременно ниже уже шёл подбор, а «Обновить подборку» была disabled. Это может подсказать лишнее ручное действие. После результата текст корректно сменился. Небольшое улучшение: та же область должна говорить, что подбор уже идёт.

### Ограничения наблюдения, не найденные дефекты

- В просмотренных ответах не было явного сравнения с невыбранной альтернативой. Null alternative разрешён контрактом, а несколько вариантов уже показаны рядом; отсутствие comparison panel само по себе не blocker.
- AI ответ с одной карточкой не назван неполным: contract разрешает 1..limit. Не утверждаю, что модель скрыла существующие альтернативы — UI не показывает весь candidate snapshot.
- Live fallback label, provider failure, timeout/retry и stale revision error в браузере не возникли и не были специально вызваны. Они остаются непроверенными этим проходом. Нельзя переносить backend test pass на UI без наблюдения.
- Не делалась проверка мобильных breakpoints, измерение контраста, полный keyboard-only audit или user study. Два кратких CDP timeout были восстановлены чтением состояния; они не доказательство зависания приложения.

## Спор и критерий смены вывода

Методологу передано: raw grounded facts — реальная объяснимость, но наблюдаемого why-A-over-B и AI uplift интерфейс не демонстрирует. Методолог прав, что цитирование всех фактов может ослабить selective explanation; это не причина оставлять prompt-only обязательства без runtime guard.

Reliability reviewer передано: stale build необходимо пересобрать; browser pass старой сборки нельзя объединять с CLI pass новой как одну оценку. После первого прохода root получил разрешение перезапустить приложение.

Сменит положительный UX-вердикт: reproducible показ будущей пользы как earned, невозможно понять следующее действие, неразличимый fallback, зависание без retry либо ошибочное смешение профилей. Сменит скепсис к добавочной AI-пользе: слепое сравнение решений пользователей с baseline и AI при одинаковом UI, где AI улучшает правильность/скорость решения без ухудшения фактической точности.

## Повторная проверка работающего UI после build

**Исправление прежней записи о процессе:** сообщение «порт 3105 остановлен» не было подтверждено и оказалось неверным. По последующей проверке root, 3105 обслуживает PID 47580, запущенный в 16:53:36 до build 16:59; прежний PID 65024 уже отсутствовал к попытке остановки. Два запуска действительно отклонялись execution policy, но это не означало отсутствие работающего приложения. Reviewer не запускал и не завершал процессы.

Старая собственная вкладка была закрыта обычной очисткой после turn. Для финального fresh-page smoke создана новая собственная Chrome вкладка **36744738** на http://127.0.0.1:3105/, сессия `🧪 AI usability`. Действия: HR → сотрудники → один профиль → один автоматический запрос рекомендаций при открытии → раскрыть первую карточку. Ручной refresh рекомендаций не нажимался; данные и config не менялись.

**Наблюдение:** страница работает; loading сменился явным «AI-подборка · проверенные сервером факты» и тремя карточками, ошибки не возникло. В раскрытой первой карточке показаны grade, skill_gap, обычный target_requirement и один conditional unlock. History и effort отсутствуют; из двух названных будущих активностей отдельный численный unlock fact показан только для одной. Это совместимо со старой серверной логикой/кэшированным AI результатом и не соответствует полноте, которую теперь требует новый guard у фактических production candidates.

**Итог:** smoke доступности и пользовательского happy path работающего сервера выполнен. **Соответствие обслуживаемого backend последнему source/build не доказано.** Нельзя назвать этот проход проверкой нового runtime guard. Он отдельно проверен offline в `adversarial/probe-after.mts`; для утверждения browser parity нужен управляемый перезапуск актуальной сборки и повторный smoke. Fallback/error/retry UI остаются непроверенными.
