# Career Quest: разбор и следующий план

Дата: 23 сентября 2026. Область этой итерации — AI-зона существующего проекта.
Основания: предоставленное официальное ТЗ «HackAlem AI: Career Quest — платформа
геймификации жизненного цикла сотрудника», фактический код поверх `15c0080`,
контракт и документы команды. Официальный набор в этой итерации не проверялся заново.

## Вывод

Выбран кейс **Halyk Bank — Career Quest**. Приоритет — доказуемая полезность следующего
шага для конкретного сотрудника и воспроизводимый полный сценарий. Дополнительные
игровые функции сейчас менее важны, чем точный допуск, прогресс, импорт профилей и объяснения.

### Проверенные требования ТЗ

| Требование | Практическое следствие |
|---|---|
| 1–3 активности и минимум три фактора объяснения | Одного ранжирования по минимальному навыку недостаточно |
| Профиль, цель, история и изменение навыков | История должна реально влиять на выбор; прогресс рассчитывается кодом |
| HR: слабые навыки, отсутствие следующего шага, участие | Нужны агрегаты реального состояния, без отдельного LLM-расчёта |
| Три дополнительных профиля жюри и история | Новые ID и противоречивые факторы должны работать без изменения кода |
| UI до 2 секунд, AI до 10 секунд | Профиль/HR отдельно от AI; измерять полный путь |
| 200 профилей, 40 активностей, 60 навыков, история 24 месяца | Проверить фактический полный snapshot и расчёт, а не только короткий пример |
| Воспроизводимый запуск | Проверить чистый clone и документированный запуск другим участником |

Распределение оценки: работоспособность 25, техническая реализация 25,
README/воспроизводимость 25, ценность 15, оригинальность 10. Первые три дают 75/100.
Это основание порядка работ, не гарантия оценки или призового места.

## Первый проход: сильная сторона текущего решения

1. **Доменное ядро отвечает за проверяемые факты.** Модель не может добавить курс,
   изменить прирост или сослаться на чужую попытку. Это помогает при неизвестных профилях жюри.
2. **Есть содержательный baseline.** Критические разрывы, остаток до цели, история,
   трудозатраты и будущая польза подготовительного шага учитываются явно.
3. **Сбой провайдера не уничтожает объяснение.** Fallback использует ту же дисциплину фактов.
4. **Демонстрируемое преимущество можно проверить.** На паре похожих профилей с разной
   историей показать, как и почему меняется рекомендация. Затем выполнить шаг и показать
   пересчёт с новой версии. Это сильная демонстрация поведения, но её уникальность не установлена.

Условие успеха этих доводов: backend должен корректно создать snapshot и факты.
Граница AI сама по себе не заменяет доменное ядро и работающий продукт.

## Второй проход: что может опровергнуть план

| Ключевое предположение | Сильный контраргумент | Дешёвая проверка / критерий пересмотра |
|---|---|---|
| Ссылки на три категории дают хорошее объяснение | Три истинных, но второстепенных факта могут сопровождать плохой выбор | Разбирать определяющий фактор на каждом конфликтном случае; три категории сами по себе не считать качеством |
| LLM улучшает ранжирование | Сильный baseline может быть столь же хорошим и быстрее | На отдельном заранее зафиксированном наборе сравнить вслепую top-1 и причины; при отсутствии преимущества снять это утверждение |
| Учёт истории полезен | Повторная неудача не означает низкую мотивацию; события с разными условиями неэквивалентны | Контрфактическая пара: изменить только историю; проверить уместность изменения и отсутствие наказания за неизвестность |
| Подготовительный курс помогает цели | Нулевой прямой прогресс выглядит бессмысленно, а будущая польза условна | Показывать конкретно открываемое событие и условие; не начислять его прирост заранее |
| 7/7 случаев подтверждает качество | Эти случаи написаны вместе с правилами; возможна подгонка | Сохранить отдельный holdout до следующей настройки промпта; затем проверить новые профили |
| AI укладывается в 10 секунд | Адаптер не измеряет сборку snapshot, БД и сеть до UI | Живой полный HTTP-прогон на большом каталоге, включая таймаут; при превышении сначала измерить источник задержки |
| Компоненты уже почти готовы | В main пока нет HTTP/БД/импорта, поэтому сквозного результата нет | Один реальный путь сотрудник → рекомендация → completion → HR → импорт до расширения функций |

### Скорректированное решение

Сохраняем LLM как проверяемый выбор и расстановку акцентов, укрепляем deterministic
fallback и связываем всё с backend. Не заявляем новизну, выигрыш по качеству или скорость
до независимой проверки. Изменить модель стоит по живым измерениям валидности,
релевантности и времени, а не по названию или цене.

## Что улучшено в этой итерации

- Целевой прирост ограничен оставшимся разрывом; посторонние навыки не завышают пользу.
- История фильтруется по сотруднику, дате и трём терминальным исходам события.
- Fallback проверяет все evidence и сохраняет определяющий факт о prerequisite.
- Единый `recommend` собирает режимы/причины сбоя; сохраняет identity и DomainVersion.
- Дедлайн, AbortSignal, отключённые SDK retries, безопасные ошибки, отказ/обрезка ответа.
- Строгий вывод без свободного текста и чисел модели.
- Семь авторских сценариев и evaluation CLI, где fallback не считается успехом AI.
- Отдельная независимая проверка нашла потерю факта prerequisite; исправление покрыто регрессией.

Проверка этой итерации на Windows / Node 24.18.0: 101 AI/domain-тест и 12 клиентских
тестов прошли; typecheck и production build успешны; offline-evaluation — 7/7 авторских
ожиданий с валидными ссылками. Проверен явный отказ live-CLI при отсутствии ключа.
Живых запросов, проверки Docker и полного HTTP-сценария в этом результате нет.

## Следующие шаги по готовности

| Приоритет | Работа | Критерий готовности | Внешняя зависимость |
|---|---|---|---|
| P0 | Snapshot, evidence и signals из backend | Один настоящий профиль проходит `recommend`; вычисления сверены | Реализация backend/каталог в локальном окружении |
| P0 | Живой smoke и семь случаев | Отчёт содержит принятые AI-ответы, время и причины провалов | Ключ выбранного провайдера |
| P0 | Сквозной путь и версии | Completion один раз изменяет прогресс; устаревший AI-ответ отклонён | HTTP, auth, БД |
| P0 | Импорт новых профилей и HR | Новые профили работают без правки кода; HR отражает изменения | ImportService и доменные правила |
| P0 | Чистый запуск | Другой участник запускает проект по README одной целевой командой | Docker/bootstrap, доступ к официальным входным файлам |
| P1 | Отдельная оценка качества | Зафиксированный holdout, сравнение минимального навыка/baseline/AI, разбор расхождений | Разметка ожидаемой пользы, доступ к модели |
| P1 | Контрфактическая демонстрация | На экране видно определяющий факт и новый результат после выполнения | Рабочий сквозной путь |

Модель ещё не проверена вживую. Официальные данные не отправлялись этим evaluation-скриптом.
Перед их использованием с облачным API нужно разрешить неоднозначность формулировок ТЗ
с организаторами; независимая разработка и авторские синтетические проверки от этого не зависят.
