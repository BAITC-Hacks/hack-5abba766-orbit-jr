# Career Quest: карта реализации

Согласовано между задачами UI и профилей/HR. Принцип интерфейса: один главный следующий шаг, показатели и графика на первом плане, объяснения и технические детали по раскрытию. Все числа берутся из API; симуляция всегда обозначается явно.

## Сквозной путь

Вход → профиль → карьерная цель → разрывы навыков → выбор обучения → симуляция → обновлённые навыки и история. HR: сводка → каталог сотрудников → конкретный профиль → изменение цели или просмотр обучения → обновление сводки.

| Часть | Текущая реализация | Представление и критерий готовности |
|---|---|---|
| Вход и права | Сессии, employee/hr, серверные ограничения | Короткая форма, понятные ошибки; сотрудник не запрашивает HR-данные |
| Профиль | Данные сотрудника, роль, грейд, подразделение | Имя из набора, инициалы, контекст; HR всегда видит, чей профиль открыт |
| Цель | Сохранение цели, версия данных | Текущая роль → целевая роль, покрытие; конфликт версии требует обновления |
| Навыки | Текущие и требуемые уровни, дефицит | Сопоставимые шкалы, выделение критичных разрывов, фильтры |
| Рекомендации | AI или явный rules fallback; проверенные факты | Иллюстрация типа, длительность, прирост покрытия в процентных пунктах; причины раскрываются |
| Каталог | Доступные активности и детали | Фильтры, даты, формат, условия; просмотр каталога сам по себе не назначает обучение |
| Выполнение | Только симуляция, идемпотентные запросы | Подтверждение действия, рассчитанный эффект, защита от повторного начисления |
| История | Реальные статусы, отдельные участия и сессии | Полоса распределения, счётчики, кнопки фильтра, прогресс каждой активности |
| HR-сводка | Агрегации по сотрудникам, целям и дефицитам | Диаграммы и показатели с корректными знаменателями, переход в профиль |
| HR-профиль | Просмотр, изменение цели, симуляция от имени HR | Явное имя в действиях и модалках; автор операции сохраняется отдельно |
| Импорт | JSON/CSV, dry run, атомарная запись и повтор запросов | Файлы → проверка → результат; ошибки, лимиты и режим без сохранения доступны до отправки |
| Темы и адаптив | Светлая и тёмная темы | Общие токены, контраст, клавиатурный фокус, мобильная компоновка |
| Данные | PostgreSQL, миграции, bootstrap официального набора | Сохранность при рестарте, отсутствие исходного набора и секретов в Git |
| AI | Ранжирование допустимых кандидатов, проверка схемы и фактов | Ошибки провайдера не блокируют путь; эффект рассчитывается сервером |
| QA и запуск | Unit/client tests, build, интеграционные сценарии | Проверки перед push; live AI проверяется отдельно при настройке провайдера |

## Следующие части продукта

Это план, а не перечень уже работающих функций. Не добавлять кнопки, обещающие действие, пока нет контракта и серверной реализации.

1. **Назначение обучения.** Добавить сущность assignment (employee, event/session, HR author, срок, статус, версия), API создания/отмены и аудит. В профиле — выбор активности и подтверждение; у сотрудника — список назначений. Назначение не должно автоматически завершать участие или начислять навыки. Проверить права, повтор запроса, отмену и недоступную сессию.
2. **Комментарии HR.** Отдельная сущность заметки с автором и явно заданной видимостью. Сначала контракт доступа и журнал изменений, затем компактная лента в профиле. Не смешивать служебные заметки с данными для AI.
3. **Сообщения и уведомления.** Определить каналы и согласованные получатели, затем outbox, фоновые повторы и статусы доставки. Интерфейс должен отличать сохранённое сообщение от доставленного. В текущем проекте отправки нет.
4. **Подтверждённое обучение.** Отдельный поток подтверждения из LMS или уполномоченной роли с доказательством участия. Не переименовывать существующую симуляцию в реальное завершение. Повторная загрузка не начисляет навыки повторно.
5. **Управление аккаунтами и интеграции.** Корпоративная авторизация, provisioning, связь аккаунта с сотрудником, деактивация, политика доступа. Затем HRIS/LMS-коннекторы с отображением ошибок синхронизации.
6. **Эксплуатация.** Метрики ошибок/времени ответа, резервное копирование и восстановление, нагрузочные проверки, контроль миграций. Оценку живой AI-модели проводить отдельно от offline fixtures.

## Границы демонстрации

`/demo` — отдельный демонстрационный интерфейс с fixtures; полный сценарий HR работает через авторизованный `/hr`. Имя отображается ровно как в источнике: отсутствующие отчества не генерируются. Достижение 100% покрытия не означает автоматическое повышение. Карточки рекомендаций — альтернативные следующие шаги: их прогнозы нельзя складывать.
