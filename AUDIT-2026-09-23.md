## Что исправлено

- **P2 — SQL после AI мог продолжать ждать после отмены.** Три служебных SQL-запроса AI-соединения получили клиентский дедлайн, обработку отмены и серверный `statement_timeout=1000`. Уничтожение сокета само по себе оказалось недостаточным: PostgreSQL может не заметить его во время ожидания блокировки. Регрессии проверяют исчезновение серверного процесса, освобождение advisory lock и успешный следующий запрос.
- **P2 — auth/metadata SQL вне транзакционного помощника не имел серверного предела ожидания.** Обычный пул теперь использует lock timeout 3 секунды и statement timeout 15 секунд; соответствующие SQLSTATE становятся `503 STORAGE_BUSY`. Локальные пределы bootstrap сохранены. Проверено прекращение настоящих ожиданий, корректное состояние сессий/куки и восстановление после снятия блокировки. Это эксплуатационный сценарий обслуживания БД, не обход прав доступа.
- **Пустая подборка объясняет причину и даёт действие.** Можно открыть оставшиеся навыки или проверить условия каталога; для отсутствующей/достигнутой цели сотрудник может выбрать направление. HR не получает запрещённых действий. Текст про альтернативы скрыт при отсутствии карточек.
- **Честные показатели.** Обзор считает навыки с оценкой выше нуля и показывает размер каталога. Отдельный профиль называет каталог каталогом, отмечает расчётные демопрохождения и отделяет соответствие навыков от повышения.
- **Порядок грейдов.** Отображается серверный порядок Junior → Middle → Senior → Lead; исходные значения выбора сохранены, поэтому перестановка пунктов не меняет отправляемую цель.
- **Контраст светлой темы.** Уточнён только цвет второстепенного текста; тёмная тема сохранена. На production через MCP подтверждено улучшение проверенной пары текст/фон с 4,36 до 4,70:1.

## Проверки объединённого кода

На объединении с `74ad060` прошли:

- 468 серверных и 82 клиентских теста;
- 66 интеграционных проверок PostgreSQL, одна отдельная live-проверка пропущена штатно;
- production-сборка, включая TypeScript;
- миграция изолированной БД до `003`: сохранены 200 профилей, 2 симуляции, 3 учебные попытки и версия данных;
- после предыдущего объединения — ещё 31 реальная HTTP-проверка через запущенный Next, со своей сессией, без вмешательства в браузерные сессии.

Ранний объединённый PG-прогон один раз упал в подготовке схемы: `Hook timed out in 10000ms`. Отдельный повтор 19/19 и последующие общие 66 проверок прошли. Причину единичной задержки не установили; исходный неуспешный лог сохранён.

a05 отдельно критически проверил общий diff, вызовы изменённых SQL-помощников и реальные PG-регрессии. Новых блокеров в этих изменениях не нашёл. Серверное прекращение SQL и клиентское уничтожение соединения нужны совместно; их пределы не являются общим SLA. Получение snapshot до ограничения AI-нагрузки остаётся ограничением.

Личные MCP-проходы подтверждают конкретные действия интерфейса, а не весь SLA. Chrome не разрешил загрузить локальные файлы через расширение; в этой серии root проверил импорт только через HTTP dry-run (3 новых профиля и 44 участия, без сохранения). Браузерный импорт коллег описан отдельно в их отчёте.

Подробные протоколы, исходные неуспешные прогоны, синтетические probes и снимки находятся в приватном архиве `test-results/audit15`. Официальный ТЗ, исходный датасет и `.env` не публикуются.

## Открытая находка и границы вывода

**P2: skip-link и переход только по hash.** В проверенной сборке `609ebc3` на `/employee` и `/hr` активация «Перейти к содержимому» меняет `#main-content`, вызывает `popstate` и повторную проверку сессии. Workspace размонтируется, фокус становится BODY; локальное состояние раздела может сброситься. Обработчик сохраняется в объединённом коде. По команде завершения исправление не начинали. Возможное узкое решение: различать изменение только fragment и реальную навигацию, сохраняя проверки identity при прежнем полном URL, path/query и восстановлении страницы.

Асинхронный I/O не гарантирует UI ≤2 секунд при любой нагрузке. Общая длительность нескольких SQL-операций может превышать один statement timeout. Полный отказ сервера/сети и большой нагрузочный прогон данной серией не проверены.

Сохранённые 69/69 Luna относятся к 23 авторским случаям с повторами. a03 сверил хэши промпта и схемы, но это не независимый holdout и не доказательство превосходства над baseline. Результаты более свежего AI-адаптера отдельно сохранены коллегами. Модель продукта остаётся `gpt-6-luna`; API-ключ в Git не включён.

Практическая польза подтверждена рабочим сценарием: сотрудник видит конкретные разрывы и расчётные последствия, HR — ограничения доступного обучения. Рост реальных навыков, вовлечённости и общественный эффект не измерены. Самый сильный контраргумент: качество каталога ограничивает достижимость целей, а дополнительная польза LLM над правилами пока не показана. Независимая оценка рекомендаций и наблюдение за реальными добровольными прохождениями могли бы изменить этот вывод.
